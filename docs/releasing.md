# Releasing

Releases use GitHub Releases as the changelog surface and PyPI publishing
trigger. The release flow must be tag-first so `release-notes-scribe` can draft
the GitHub Release notes before the release is published.

## Required Local Checks

Run the canonical local validation and build before tagging:

```bash
pdm run check
pdm build
```

`pdm run check` runs lint first, then the full pytest suite.

## Process

1. Choose the next semantic version tag, using an unused version tag.
2. Replace `vX.Y.Z` below with that version, then create and push the tag:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

3. Wait for the `Create Draft Release` workflow to complete.
4. Review the drafted GitHub Release generated by
   `btfranklin/release-notes-scribe`.
5. Publish the GitHub Release.
6. Confirm the `Upload Python Package` workflow completes.

## Workflow Boundaries

- [Draft release workflow](../.github/workflows/create-draft-release.yml) runs on
  pushed `v*.*.*` tags and drafts release notes with
  `btfranklin/release-notes-scribe`.
- [Python publishing workflow](../.github/workflows/python-publish.yml) runs when
  a GitHub Release is published, builds with PDM, and publishes to PyPI through
  trusted publishing.
- Versioning is SCM-derived through the PDM configuration in
  [pyproject.toml](../pyproject.toml).

Do not publish the GitHub Release before the tag-triggered release-notes workflow
has populated the draft. The PyPI publishing workflow does not generate release
notes.
